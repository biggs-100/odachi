# a-review-answer

## What must exist
- a review answer that cannot be read is kept, named and attachable again, so the same answer is never paid twice

## Done when
- an answer that cannot be read -verdict or refutation- is written in the ignored store under a name its own bytes decide
- the blockage names the file and the command that attaches it again
- two different unreadable answers for one tree coexist; the same bytes are written once
- an answer that lands leaves no kept file behind for that tree
- tests pin the kept bytes, the name, the coexistence and the cleanup

## Not included (first version)
- repairing the answer (ANSI, banners): the human repairs it before attaching
- a reviewer that could not run, timed out or exited nonzero: no answer exists to keep
- teaching --attach to accept a raw stream
- the panel itself

## Decisions taken
- It is used from the computer.
- There is no sensitive data in the first version.
- First usable version: today.
- Wants to learn: how a paid answer survives a tool's refusal.
