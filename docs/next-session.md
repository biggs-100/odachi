## What this cycle learned

- **A batch is a sentence, not a list.** The proof and the verdict are owed by the
  closing tree, so three debts that fit one promise cost one proof and one verdict;
  the only thing that stays per-debt is the commit. 0325 paid the boundary, the two
  readings and the model for the price of one close, and the sentence that held
  them was "the verdict judges the candidate and nothing else".
- **A slice is not the candidate.** A prompt too big is split, so one reviewer reads
  a part of the diff, but the directory it reads holds the whole tree: a
  declaration naming a path from another part is not an invention. Judging the
  invention against the slice is what made `--exec` refuse an answer `--attach`
  accepted for the same bytes.
- **A refusal is cheaper than a merge.** Two configurations with two precedences
  cannot be merged from above: the client reads the nearest one, so the only
  honest way to keep the boundary is to refuse the candidate that carries one.
- **The answer is the only first-hand account of who judged.** `--model` exists
  where a command carries a placeholder; an answer attached by hand says it in its
  own field. A store that keeps neither leaves the reader to the project's table,
  which names who was asked, not who answered.
- **A feature's base is a commit the remote has.** `0323` pointed at the previous
  session's note, which was never pushed; `0324` pointed at a commit that lived
  only on its branch, and the squash erased it. CI answered `bad object` and read
  nothing, twice, for the same reason. The squash is the moment to check the base,
  not the next pull request.
- **A sentence in a prompt is not a boundary.** The blind arm of the second run
  cited `auth.go` with no snapshot, and the tool log said how:
  `Glob "**/auth.go" in C:/Users/USER/AppData/Local/Temp · 4 matches`. What holds
  is `external_directory: deny` in the configuration the client discovers from the
  location it runs in, and it holds for `read`, `glob` and `grep` at once.
- **The reviewer's working directory was the project.** The snapshot was named in
  the prompt and the command ran in the live worktree, so the reviewer could read
  the bytes that may move under the verdict. It runs in the candidate now.
- **The nearest configuration wins.** A boundary written one level above the
  candidate is voided by an `opencode.json` the candidate carries, because the
  client merges from the farthest ancestor to the nearest. A rule that lives in a
  file has a precedence, and the precedence is part of the rule.
- **A model narrates before it answers.** `review probe` read stdout as the
  verdict and refused a paid answer; `review --exec` kept a refused one the same
  way. The object is now cut out of the answer and the store keeps the whole text.
- **A median with a range is not a total.** `clean noise 0 (0..1)` is a median of
  zero with one draw of three raising a claim; the page said "no claim at all" and
  the review caught it. Read `span` before writing a sentence about a number.
- **`golangci-lint` is not in CI.** The floor's lint row is CRITICAL and only
  `review` runs it, so three unchecked lines shipped in 0321 and 0322 and the next
  verdict refused to store until they were paid. A check nobody runs on the merge
  is a check that rots.
- **`--attach` merges the floor's rows.** A red check turns an approved answer
  into a refusal that speaks about the rule deriving `changes_requested`, not
  about the lint that made it.
- **The commit hook wants the proof of the exact tree being committed** once every
  step of the feature is done. Stage everything, measure, then commit.
- **An answer key counts a line, not a claim.** A finding about missing tests at
  `server.go:23` scores as the context defect at line 24. The `evidence` field and
  reading the `why` are the only separations the instrument has.

## The commands that work

```sh
odachi check --run "go test ./..." --timeout 1800
```

```sh
# prove a guard by breaking it: the string out, the failure has to name the text
odachi check --run "go test ./..." --mutate <file> --remove "<string>" --expect "<text>"
```

```sh
# the record the close owes: one command, the prompt on stdin, the answer on stdout
odachi verify --exec 'C:\Users\USER\AppData\Local\Temp\odachi-ver.bat {prompt} C:\Users\USER\AppData\Local\Temp\verify.json'
odachi verify        # the prompt it would ask, and nothing runs
```

The verifier's wrapper cuts the JSON object out of the answer: the model narrates
first and `odachi verify` requires exactly one object.

```sh
# the review of a closing tree: the lenses the evidence asks for, two draws each
odachi review --runs 2 --base <feature base> --exec 'C:\Users\USER\AppData\Local\Temp\odachi-rev.bat {model} {prompt} C:\Users\USER\AppData\Local\Temp\review.json'
```

```sh
# a correction measures the delta, carries the predecessor's rows, takes no --base
odachi review --since <tree prefix> --runs 2 --because "<why>" --exec '<the same command>'
```

```sh
# the probe: two arms, three draws, the same binary for both
odachi review probe --runs 3 --exec '<the reviewer command without {model}>'
odachi review probe --runs 3 --blind --exec '<the same>'
```

## The limits to remember

- **A Windows CI test that depends on PowerShell startup needs a budget for the
  runner.** Ten 300 ms lines with 3 s and 2 s bounds, as 0321's streaming test
  carries. Even that budget breaks under load: v0.49.1's gate failed once at
  11m41s and passed on a rerun at 7m18s, on the same bytes.
- **A candidate that ships its own `opencode.json` cannot be reviewed.** The client
  reads the nearest configuration, so odachi refuses the candidate instead of
  running a reviewer whose boundary the candidate set. A project that keeps one at
  its root needs it removed -or renamed- before the frozen run.
- **`--model` still needs `--exec`.** It replaces `{model}` inside a command; an
  answer attached by hand names its model in its own field, and the store keeps
  that name per lens.
- **A document commit after a close leaves the local `check` red**, on purpose: CI
  regenerates its own proof from a clean checkout.
- **The note's totals are written after the last step is marked**, from
  `odachi summary`, never typed.
- **A document commit after a close leaves the local `check` red**, on purpose: CI
  regenerates its own proof from a clean checkout.
- **The proof names the index tree** (`git write-tree`).
- **A schema bump needs the tree's binary ahead of the installed one.**
- **`## Unreleased` has to be re-created after every release**, and the release is
  minor when the stored shape moves.
- **A release is a tag on the merge of the release pull request.** A version is
  never moved or reused.
- **`windows-latest` is the slow gate**: three to eleven minutes against one to
  four for the others.
- **The fence is read from the base**: a policy change lands first, in its own
  pull request.
- **One heavy gate per machine**: `go test ./...` takes about twelve minutes here.
- **PowerShell's `Set-Content -NoNewline` on an array joins the lines**, and a
  backtick inside a double-quoted replacement is an escape: write whole files with
  the file tool.
