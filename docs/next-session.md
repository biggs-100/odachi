## What this cycle learned

- **Compare code, not READMEs.** Three read-only explorers over gentle-ai's source and
  odachi's source produced the shortlist; four claims were spot-checked directly. Two
  ideas were rejected with evidence: derivation labels add nothing when every bench
  number comes from a real process, and the dead-end classifier already existed in
  `internal/app/bench` plus the new gate guard.
- **A fence rule protects a path, not its reason.** Touching
  `.github/workflows/gate.yml` needed a brief non-goal and a narrower fence merged to
  main first; CI reads the fence from the base ref. A commit on the feature branch was
  refused by the hook until the branch was rebased onto that policy merge.
- **A gate that never gets a runner is not a gate.** 0192 moved off `macos-latest`
  because the arm64 pool never assigned one. The reversal was conditioned on seeing the
  job assigned and green before the ruleset was reapplied; it passed in 2m20s.
- **A wrapper covers every return branch.** `withTransition` in `gate.go` derives the
  typed continuation from the code and the command, so a future reason cannot forget it.
  The test-first RED was a build failure because the type did not exist yet.
- **A stale local main corrupts the record.** A `git fetch` without `git pull` made
  `odachi start --light` reuse feature number 0348 for a second doc. Pull before branching.
- **Proofs that include `cmd/odachi` need `--timeout 2400` here.** 1200 times out because
  the gate runs the suite twice; a narrower command was enough for the smaller features.
- **A reported number must be assigned, not just declared.** `bench --json` carried an
  `interactive` field that was never filled, so every reader saw zero. Reading the code,
  not the output, found it.
- **Light features do not write release notes.** 0348-0351 needed `## Unreleased`
  written by hand before any release, because `start --light` only writes a task doc.
- **An unjudgeable undo row is a note.** Features 0349 and 0351 changed constants and
  signatures together, so the reverted copy did not build; the gate said so and let the
  close proceed.

## The commands that work

```sh
# a close, then ONE proof on that tree, then the commit -in that order
odachi plan --done T1 --commit <sha>
odachi check --run "<command>" --timeout 2400
git commit -m "..." -m "Risk: none"
```

```sh
# build the tree binary per feature and lead PATH before anything that must know this tree
go build -o "$env:TEMP\odachi-next-bin\odachi.exe" ./cmd/odachi
$env:PATH = "$env:TEMP\odachi-next-bin;$env:PATH"
```

```sh
# carry one close's evidence out of the clone
odachi evidence export <40-or-64-hex-tree> --out "<temp>\bundle.json"
```

```sh
# the release: a branch that renames Unreleased, a PR, then the tag on its merge
git switch -c release/vX.Y.Z && git commit -am "release vX.Y.Z" --no-verify && gh pr create --base main
git tag -a vX.Y.Z <merge commit> -m "vX.Y.Z: <the sentence the notes carry>" && git push origin vX.Y.Z
irm https://github.com/biggs-100/odachi/releases/download/vX.Y.Z/install.ps1 | iex
```

```sh
# rerun one failed job, only after every job in the workflow run has concluded
gh api -X POST repos/biggs-100/odachi/actions/jobs/<job id>/rerun
```

## The limits to remember

- **The gate runs the proof and its reverted copy.** `cmd/odachi` alone costs 212-307s
  here; one `check --run` with it is about ten minutes. Never add a second full suite.
- **The reviewer's clock is 600s and the verifier's is 1800s**, with a 120-second silence
  budget on both. If one provider hits its usage limit, switch provider, not the method.
- **A feature's base is a commit the remote has**, and a squash erases a branch-only base:
  rebase before retargeting. `git rebase --onto` takes the old base as the upstream.
- **The fence is read from the base**: a policy change lands first, in its own pull request.
- **`## Unreleased` is re-created after every release**, and a version is never moved or
  reused: the tag lands on the merge of the release pull request.
- **A document commit after the close leaves local `check` red**, on purpose: CI
  regenerates its own proof from a clean checkout. Release commits use `--no-verify`.
- **The proof names the index tree**, and `proof/` is gitignored, so the closing tree never
  carries it: the link is the `# tree` header. `odachi evidence export` is the explicit
  way to take it out.
- **`windows-latest` is the slow CI gate**: 7-10 minutes in this cycle. macOS is back on
  `macos-latest` and was assigned on every attempt.
- **The wrappers live in temp**: `odachi-rev2.bat`, `odachi-ver3.bat` and `odachi-cut.ps1`.
  If the folder is emptied, compose them again.
