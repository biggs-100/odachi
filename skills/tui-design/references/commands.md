# The playbooks

One command, one named target —a panel, a bar, a card type. Every refine command ends with `polish`.

## shape — plan before the code

- Two or three questions per round: what it is for, who uses it and how often, what success looks like.
  Then the content ranges, the states and the widths it must survive.
- Output a brief: goal, users and frequency, content inventory with its ranges, states, layout at each
  width, the keyboard model, open questions. No code.

## distill — remove what does not earn its rows

- One primary goal per panel; each fact once per screen.
- Flatten the nesting; delete a group title that only restates its content.
- Collapse finished or idle content to a summary row.
- Distill the rail's contents; never argue away the rail itself.

## layout — space and rhythm

- The squint test first: fix the order before the decoration.
- Proximity, then a separator, then a box.
- Tight inside a group, one gap between groups.
- Align values in a column; tabular figures for anything counted or timed.

## typeset — hierarchy without font sizes

- Three or four roles: title (bold or accent), value (normal), label (dim), meta (dim italic).
- Apply each role identically everywhere it repeats.
- Prose wraps at 60-80 columns; chrome truncates.

## quieter — turn it down

- Fewer surfaces, fewer accents, no decorative motion.
- Keep the anchors: the accent on the active item, the one number that leads.

## bolder — amplify one thing

- Touch only the named target, and amplify what the system already owns.
- One move, and everything around it quiet.
- The skeleton test: the structure still reads with placeholder text.

## colorize — roles, not swatches

- Map every colour to a role; accents only for action, selection and live state.
- A second neutral for rails and bars, with its contrast checked.
- A state colour always travels with a glyph or a word.

## clarify — the copy

- A control names its action. An error says what failed, why, and how to recover.
- An empty state says whether it is first use, nothing yet, or a failure.
- Loading names the operation; never fake progress.
- One term per concept across the whole interface.

## harden — the edges

- Long paths and branch names, emoji and CJK widths, 0 / 1 / 1000 items, a task that never finishes.
- Missing data, a failed command, a permission error: one failing part never blanks the surface.
- A resize during a render, and the collapsed and expanded forms of every section.

## adapt — other widths

- Rethink per width, never scale: 180, the breakpoint, 80x24.
- Decide what moves to the status bar or behind a key when the rail is gone.

## polish — the last pass

- Classify each drift: a missing token, a one-off value, a concept mismatch, a local defect.
- Triage: broken task, missing state, flow, visual, cleanup.
- One glyph family, every control in every state, no stray colour.
- Re-capture and compare with the brief and with the previous frame.

## document — the context

- Write or update the terminal section of `design/system.md`; propose a diff, never overwrite it
  silently.
